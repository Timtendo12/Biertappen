# Biertappen

A mobile-first drinking card game played by a group sharing **one phone**. Enter
everyone's names, pick a deck, tap to flip a card, swipe it away, and the next
one deals itself.

Dutch-first, English supported. Installable as a PWA. Works with or without
alcohol.

---

## How it fits together

The single decision the codebase is organised around:

> **The game engine is a pure TypeScript module.** `resources/js/game/` imports
> no Vue, touches no DOM, and makes no network calls.

The deck is fetched **once** when a game starts; every card after that is
selected and resolved locally. That is what makes card transitions instant, and
it means every rule — who is picked, whether a card can repeat, when the game
ends — is testable without rendering anything. PHP never resolves a variable.

```
Deck (JSON)  →  engine: eligibility → shuffle bag → variable resolution  →  ResolvedCard  →  UI renders
```

The UI decides nothing. It calls in and draws what comes back.

### Cards are structured, not templated

A card is an ordered list of segments, never a string with placeholders:

```json
[
  { "type": "variable", "value": "player1" },
  { "type": "text", "value": " neemt " },
  { "type": "variable", "value": "amount", "options": { "mode": "range", "min": 1, "max": 4 } },
  { "type": "text", "value": " slokken." }
]
```

Nothing ever scans text for `{player1}`. The format is a documented public
contract — see [`docs/deck-format.md`](docs/deck-format.md) — so decks can be
written by hand, generated by an AI, exported, and re-imported losslessly.

`resources/deck/variables.json` is the one definition of what a variable is,
read by both the TypeScript engine and PHP validation so they cannot drift.

## Stack

| | |
|---|---|
| Backend | Laravel 13 (PHP 8.3+), MariaDB |
| Frontend | Inertia 2, Vue 3.5, TypeScript, Tailwind 4 |
| Auth | Fortify (email/password) + Socialite (Google) |
| Payments | Lemon Squeezy — Merchant of Record, so no company registration needed |
| Editor | Tiptap atomic nodes, lazy-loaded so players never download it |
| Tests | Pest, Vitest, Playwright |

## Getting started

```bash
composer install
npm install
cp .env.example .env
php artisan key:generate

# MariaDB
php artisan migrate --seed

npm run dev          # in one terminal
php artisan serve    # in another
```

## Tests

```bash
php artisan test     # Pest — backend, contract, authorisation, webhooks
npm run test         # Vitest — engine, editor mapping, components
npm run typecheck    # vue-tsc
npm run test:e2e     # Playwright — the gameplay loop in a real browser
npm run build        # must pass: it is the deploy artifact
```

Backend tests run against **MariaDB**, not SQLite: the entitlement and webhook
idempotency guarantees rest on real unique-constraint behaviour, which the two
engines model differently.

Four tests exist to catch things nothing else would:

- **`MassAssignmentSafetyTest`** — privilege columns (`users.role`,
  `decks.share_token`) are deliberately not fillable, so `->update()` drops them
  *silently*. This has caused real bugs where a controller flashed success and
  changed nothing.
- **`InertiaPagesExistTest`** — a controller rendering a missing Vue component
  fails only in the browser, with a blank screen no test or build would catch.
- **`DocumentedExamplesTest`** — every JSON example in `docs/deck-format.md` is
  extracted and actually validated, so the documentation cannot drift from the
  validator.
- **`DeckFormatTest`** — a deck exported and re-imported must come back byte for
  byte.

## Layout

```
app/
  Domain/Deck/      validator, importer, exporter, variable registry
  Domain/Billing/   checkout + entitlement services
  Policies/         DeckPolicy — every deck authorisation decision
resources/js/
  game/             the engine — no Vue, no DOM, no network
  creator/          Tiptap chip node + segment mapping
  pages/            Inertia pages
schemas/            the published deck JSON Schema
docs/               deck format + deployment
deploy/             release builder and DirectAdmin web-root files
e2e/                Playwright
```

## Deployment

Shared DirectAdmin hosting with no SSH: releases are built locally and uploaded,
and migrations run via a scheduled command triggered by a file.

See [`docs/deployment.md`](docs/deployment.md).
